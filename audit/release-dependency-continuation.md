## Storage changes and compatibility boundary

`storage/application.rs` adds bounded semantic namespace activation:
`NamespaceMigration`, `MigrationTarget`, `apply_migration`, `migration_target`,
and `Error::Fenced`. Activation validates nonempty, sorted, distinct source
namespaces (maximum256), checks exact source heads in the transaction, and stores
immutable source-to-target/manifest fences. Ordinary subsequent writes to a
fenced source fail; exact historical retries are checked first and remain usable.

The existing migration status slot receives `neuron-v1`. Current Database open
accepts that completed status or `complete`; older binaries reject `neuron-v1`.
Consequently, reopening an activated database with an older binary is unsupported
by design, even though public state certificates remain compatible. Semantic
mapping, authorization and fingerprint framing belong to the application adapter,
as stated in `specs/application-storage.md`.

The seven native record domains already existed in the rehearsal. Latest
`records.rs` and `backend_fjall.rs` changes are formatting and SSD-only gating of
`RecordDomain::ALL`. Added tests exercise shared native/application/shard commits,
rollback, bounded reads/scans, reopen and injected storage failures. These changes
do not insert application records into the public certificate tables.
